How to use the FHIR Validator

The FHIR Validator checks HL7® FHIR® R4 resources in JSON. It runs in your browser. Nothing you paste or open is uploaded.

Checking a resource

  • Paste a resource into the editor, or use Open file for a .json file.
  • You can also drag a file onto the editor.
  • Load example loads a valid R4 Patient. Use it to try the tool.
  • Choose Validate, or press Ctrl+Enter (Cmd+Enter on a Mac).
  • Format tidies the indentation, and Clear empties the editor.

Reading the results

The summary at the top shows that the resource is valid, or it shows the number of errors and warnings. Each problem below the summary shows a message, the element path and the line number. Click a problem to go to that line in the editor. Markers beside the line numbers show the same problems.

An error means that the resource breaks the specification. The tool has only two warnings: a Coding with a code but no system, and a Quantity with a value but no unit or code.

Nothing is uploaded

The validator runs on this device. The content security policy on this page blocks all outbound connections, so nothing you paste or open can leave.

What it checks

The rules come from the official HL7® FHIR® R4 (4.0.1) definition files.

  • JSON syntax, with the line and column of the problem.
  • That resourceType is present and is a real R4 resource type.
  • Unknown elements, with a suggestion when there is an obvious near match.
  • Cardinality: required elements, and arrays versus single values.
  • Data types, recursively through complex types such as HumanName and Identifier.
  • Primitive formats, including real calendar dates.
  • Choice elements: at most one present, and only an allowed type.
  • Codes for elements with a required binding, where the spec fully lists the codes.
  • JSON rules: no nulls or empty values, and correct primitive extensions.
  • Nested resources: contained resources, bundle entries and any other resource element.

What it does not check

It does not check FHIRPath invariants, terminology (for example, whether a LOINC or SNOMED code exists), or profiles and implementation guides such as US Core. It reads JSON, not XML, and it covers R4 only. For full conformance checks, use the official HL7® validator.
